# 第一批查询性能优化验收

## 已实现
- `lib/aggregate-cache.ts`：最多 128 项、约 8 MiB 结果、5 分钟 TTL 的服务端内存缓存；SQL、绑定参数和完整 sourceVersions 共同作为键；只缓存已完成的聚合数据，不缓存身份或设置。
- `lib/query.ts`：概览与指标拆解共用同一周期原始聚合；保持原有空值、去重和公式口径。
- `lib/discovery/aggregation.ts`：增加月份范围条件，复用已有月份/导入版本索引；不新增数据库索引或改变导入结构。
- `lib/discovery/analysis.ts`、`service.ts`：分析与 discover 复用缓存层。
- `lib/client-cache.ts`：浏览器合并相同在途请求；取消一个消费者不影响其他消费者。
- API 响应提供 performance 和 Server-Timing（概览、analysis），区分实际执行聚合、命中、数据库耗时和总耗时。

## 查询次数
同一服务实例、相同 sourceVersions、缓存未过期时，按顺序操作：
| 操作 | 原重型聚合数 | 新实际重型聚合数 |
|---|---:|---:|
| 有上期的概览冷查询 | 6 | 5 |
| 概览后打开指标拆解 | 1 | 0 |
| 之后扫描渠道与设备 | 3 | 2 |
| 同范围切换另一个指标扫描维度 | 3 | 0 |

概览每次另有两次轻量版本读取（原来一次），用于防止导入期间返回混合版本。缓存命中不等于整个接口零数据库查询。

## 验证
- TypeScript、既有分析与维度测试、新增性能/缓存测试、生产构建通过。
- 8 种筛选范围与原始 SQL 对照通过，包括渠道、设备、联合筛选、空分组、无上期、多月与样例。
- 校验跨 KPI 复用、版本变化失效、旧 expectedSourceVersions 拒绝、失败查询不缓存、缓存数据防篡改，以及浏览器请求合并/独立取消/重试。
- 已知 2017-03 与 2017-02 汇总数据的既有 Shapley 和守恒测试通过；未重新取得线上完整 GA 数据。

## 本地基准（非线上）
合成 SQLite 数据 120354 行，已有 sessions_month_import 索引；每个范围 SQL 执行 7 次取中位数：
- 原查询：42.61 ms。
- 增加月份范围：26.75 ms。
- 单次缓存冷读聚合：26.13 ms；热读：0.022 ms。
这些数据不包括 D1 网络往返、浏览器加载和真实 GA 分布，不能作为线上加速承诺。

## 限制与下一步
这是 Worker 实例内缓存；实例重启或请求进入其他实例会冷查，不是跨实例持久化缓存。首次元数据查询没有调整，也没有拆分首页接口。
线上冷查询与端到端耗时仍待验收：测首次打开、3 月切换筛选、GMV→交易数→访客→维度下钻；记录 performance.aggregation.hits/executed/databaseMs 和 performance.serverMs，再决定持久化缓存或索引调整。

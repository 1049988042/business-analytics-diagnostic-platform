# 自动发现 P1

扫描入口 GET /api/discover?input=JSON。仅使用 months 当前指向的已确认 GA 数据；样例禁止业务扫描，通用字段映射数据集尚未接入。程序直接运行参数化 SQL 和规则，没有模型调用、没有虚构结果。

默认取侧栏所选月份中最新月（全部则全部数据最新月），若紧邻上月存在则比较整月，否则采用该月最后可用日期截至的两组七天。也可明确选择整月或七天。上期不必在侧栏所选月份内，页面列出实际日期。覆盖不足时停止，不能跳过缺失月份与更早月份比较。日期以原始 GA date 为准。

全局每日覆盖单独检查，再应用渠道/设备筛选。全店有记录但选中分组没有会话的日期才可认为分组为零。周期访客按原始标识 COUNT DISTINCT，不汇总日访客；金额/交易按同一周期会话求和；阶段比例使用行为交集，不假设顺序。

## 规则

- 数量、金额相对变化 >= 15%。分母为零时不用 Infinity，上期为零只报绝对增长。
- 比例变化 >= 0.3pp 且相对变化 >=10%；零基数不计算相对变化。
- 访客两期均 >=200；购买人数至少一期 >=20；购买转化率同时满足两期访客 >=200 与至少一期购买人数 >=20。
- 收入、交易至少一期交易 >=20；客单价两期交易都 >=20。行为比例两期行为分母都 >=100。
- 收入/访客与购买转化率都达到规则阈值且方向相反时生成背离卡。
- 渠道/设备两期总收入各 >=1000 USD，分组至少一期 >=20 交易，占比变化 >=5pp。
- 日度收入与前七个连续日的均值比较，偏离 >=50%、绝对差 >=100 USD、当天或参考期日均交易 >=10。

所有规则是探索性筛选，不是统计显著性检验，不推断因果。日度规则未校正星期、节假日和促销。月总量天数差异醒目提示，并给出日均收入、日均交易。阈值未达到或样本不足均保留实际指标与原因。

## 指标关系

收入 = 交易数 × 客单价。
交易数 = 购买人数 × 每购买用户交易数。
购买人数 = 访客数 × 购买转化率。

分母为零则相关比例为空。相邻行为交集率不能连乘得到全店购买转化率。本阶段仅展示关系，P2 再做因素拆解、贡献度和自动下钻；AI 报告留到 P3。

## GMV 拆解与渠道贡献

同一对比周期内，交易数贡献 = Δ交易数 × 两期客单价均值，客单价贡献 = Δ客单价 × 两期交易数均值。两项精确加总为 GMV 差额；任一期交易数为零时不生成因素贡献。该对称分摊是算术关系，不是因果判断。

渠道及渠道内设备按本期金额减上期金额计算贡献，按贡献绝对值排序。两期任一期存在的分组均保留。净变化占比可为负或超过 100%；净变化绝对值不足 0.01 USD 时不计算。渠道与设备为上下级分解，不跨层相加。金额展示四舍五入，底层计算不预先舍入。

渠道×设备在一次 SQL 分组中返回，同时供结构扫描与贡献展示使用，不新增点击请求。SQL、参数、导入版本与原扫描结果一起保留。tests/contribution.mjs 验证因素守恒、反向对称、抵消、新增与消失渠道、零交易和筛选后的 SQL 结果。
